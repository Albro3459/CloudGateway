## Confirmed findings

### P1: A region timeout hides a confirmed client-query authorization denial

- Location: `/Users/alexbrodsky/GitHub/CloudGateway/Frontend/Apple/macOS/CloudGateway/CloudGatewayMacInventoryService.swift:96`
- Trigger: With an authorized cache, start an inventory refresh. The access check succeeds, then the parallel Instances read returns Firestore permission-denied while the Regions read never obtains a server snapshot and reaches its ten-second timeout. An admin downgrade between the access check and the collection-group read is one concrete source of the denial. The delayed region read is the timing prerequisite, not a claim that every downgrade produces this race.
- Evidence: Both reads start at `/Users/alexbrodsky/GitHub/CloudGateway/Frontend/Apple/macOS/CloudGateway/CloudGatewayMacInventoryService.swift:81` and `/Users/alexbrodsky/GitHub/CloudGateway/Frontend/Apple/macOS/CloudGateway/CloudGatewayMacInventoryService.swift:88`. The tuple at line 96 awaits Regions first. Its timeout throws `.offline`, and scope cleanup discards the already-failed Clients child without observing that child's `.accessDenied`. The listener/error mapper at `/Users/alexbrodsky/GitHub/CloudGateway/Frontend/Apple/macOS/CloudGateway/CloudGatewayMacInventoryService.swift:156` and `/Users/alexbrodsky/GitHub/CloudGateway/Frontend/Apple/macOS/CloudGatewayMacCore/Sources/CloudGatewayMacCore/CloudGatewayMacInventoryError.swift:28` classifies the client denial correctly, but the parent never propagates it. The controller's offline catch at `/Users/alexbrodsky/GitHub/CloudGateway/Frontend/Apple/macOS/CloudGatewayMacCore/Sources/CloudGatewayMacCore/CloudGatewayMacController.swift:424` reloads the old cache and sets `hasAuthorizedInventory = true`; its denial path at line 443 is skipped. The Instances rule at `/Users/alexbrodsky/GitHub/CloudGateway/Backend/Firebase/firestore.rules:89` rejects the unfiltered query after admin access is removed.
- Impact: A confirmed authorization rejection becomes offline authorization. In the downgrade scenario, cached configs for other users can remain connectable, and cached authorization is not invalidated. This differs from the documented limitation that revocation cannot be observed while offline: this read did observe a rejection.
- Fix direction: Preserve the results of both inventory reads and make authorization rejection dominate a sibling transport failure. Alternatively propagate an authorization rejection immediately and cancel the sibling. Ensure an already-received denial cannot be discarded by tuple-await ordering.
- Validation: Confirmed by static control-flow review. The original implementation read Regions before starting Clients, so it did not discard a concurrently received client denial this way. A deterministic regression would hold Regions until timeout and fail Clients with permission-denied first; execution is left to the main agent under the requested review-only scope.
